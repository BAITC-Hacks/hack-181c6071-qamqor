# Git-процесс без смешивания работы

## Главное правило

Перед новой задачей прочитать `docs/ACTIVE_WORK.md`. Один баг или функция одновременно принадлежит только одному участнику. Обнаружение бага не означает разрешение его исправлять.

Один центральный repo, три отдельных локальных клона, один владелец каждой ветки:

| Ветка | Единственный автор | Файлы и решения |
|---|---|---|
| `feat/core` | Али | каркас, зависимости, общие типы, engine, API, deploy |
| `feat/ui` | Даурен | компоненты, страницы, стили, мобильный UI |
| `feat/ai-data` | Димаш | fixtures, тесты, объяснения, README |

В `main` напрямую после стартовых документов никто не push. Али объединяет готовые изменения через Pull Request по одному: сначала core, затем data, затем UI.

## Начало работы

Каждый клонирует repo в отдельную папку на своём ноутбуке и переключается на свою уже созданную ветку:

```powershell
git clone https://github.com/BAITC-Hacks/hack-181c6071-qamqor.git
cd hack-181c6071-qamqor
git switch <своя-ветка>
git branch --show-current
git status
code .
```

Не копировать `.git` между ноутбуками, не работать всем в одной сетевой папке и не переключать чужую ветку в своём рабочем клоне.

## Перед commit

```powershell
git branch --show-current
git status
git diff
git add <только-свои-файлы>
git diff --cached
git diff --cached --check
git commit -m "feat: краткий законченный результат"
```

Не использовать `git add .`, пока участник не посмотрел `git status`. Не добавлять `.env.local`, токены и файлы чужой зоны.

## Перед push

Поскольку у каждой ветки один владелец:

```powershell
git push -u origin HEAD
```

Если push сообщает, что remote впереди, остановиться и написать Али. Не применять `--force`.

## Pull Request и объединение

1. Участник открывает PR из своей ветки в `main`.
2. В PR пишет: что работает, как проверить, какие файлы изменены.
3. Али просматривает Files changed и запускает проверку.
4. Али объединяет только один PR за раз.
5. После merge остальные синхронизируются:

```powershell
git fetch origin
git merge origin/main
```

Если появился конфликт, участник не выбирает вариант наугад: сообщает Али имена конфликтующих файлов. Общие `package.json`, lockfile, типы и API-контракт разрешает Али.

## Кто что не меняет

- Даурен и Димаш не устанавливают npm-пакеты самостоятельно; просят Али.
- Даурен не меняет engine, CSV loader и API-контракт.
- Димаш не меняет страницы и стили.
- Али не переписывает UI/fixtures без сообщения их владельцу.
- AI-исполнитель работает только в текущей ветке и сначала читает `AGENTS.md`.

## Документация

Документы лежат в repo как единый источник требований. Каждый читает `AGENTS.md`, `docs/CASE.md`, `docs/TASKS.md` и свой prompt. `docs/IMPLEMENTATION.md` обязателен Али и Димашу. Архивы handoff нужны только для передачи инструкций; их содержимое повторно в repo не копируется.
