# Координация трёх участников

## Единственный источник истины

`origin/main` — собранный проект. `docs/ACTIVE_WORK.md` — текущие назначения. Только Али меняет назначения и объединяет код.

## Порядок получения задачи

1. Участник пишет Али: `свободен, ветка ..., HEAD ...`.
2. Али выдаёт один ID из `ACTIVE_WORK.md`, ожидаемый результат и разрешённые файлы.
3. Участник синхронизирует `origin/main` и сообщает AI четыре поля из AGENTS.
4. AI делает только назначенную задачу.
5. Участник проверяет результат и push своей ветки.
6. Участник сообщает Али: ID, SHA, проверка, изменённые файлы.
7. Али интегрирует или возвращает конкретное замечание.

## Сообщение о баге

```text
BUG: краткое название
Ветка/HEAD:
Шаги:
Ожидалось:
Получилось:
Файл/экран:
```

До назначения владельца баг не исправлять. Второй нашедший воспроизводит его и прикладывает наблюдение, не создаёт patch.

## Разрешённые зоны файлов

| Участник | Может менять без дополнительного решения |
|---|---|
| Али | `package*.json`, config, `src/lib/**`, `src/app/api/**`, `.env.example`, deploy |
| Даурен | `src/app/components/**`, визуальные части `src/app/page.tsx`, UI CSS |
| Димаш | `tests/**`, `data/fixtures/**`, README, demo-сценарии; LLM-модуль после отдельного назначения |

Общие `AGENTS.md`, `docs/ACTIVE_WORK.md`, типы и API-контракт меняет Али. Если задаче нужен чужой файл, участник пишет предложение Али и ждёт назначения.

## Синхронизация

Перед началом назначенной задачи:

```powershell
git status
git fetch origin
git merge origin/main
git branch --show-current
git log -1 --oneline
```

При конфликте остановиться. Не выбирать `ours/theirs` автоматически. Прислать Али список из `git status`.

## Интеграция Али

Али сравнивает ветку с `main`, проверяет только заявленные файлы, запускает `npm run check` и `npm run build`, затем объединяет одну ветку. После merge сообщает новый SHA всей команде и обновляет `ACTIVE_WORK.md`.
