# Реализация #79-lite

## Пайплайн

1. Нормализовать запрос: пробелы, регистр, числовой бюджет и длительность.
2. Найти записи нужного города и категории.
3. Если таких записей нет — исход `NO_CATEGORY_IN_CITY`.
4. Отфильтровать занятых на дату, дороже бюджета, неподходящий формат, язык и недостаточный `max_hours`.
5. Если кандидаты были, но все исключены — исход `NO_ELIGIBLE`, вернуть агрегированные причины и количества.
6. Для прошедших кандидатов рассчитать прозрачный score по совпадениям. Tie-break всегда по стабильному `id`.
7. Взять первые три и построить индивидуальные объяснения только из доказанных факторов.

## Детерминированный score

Начальная версия без LLM:

- точное совпадение формата: обязательный фильтр;
- дата свободна: обязательный фильтр;
- цена не выше бюджета: обязательный фильтр;
- запрошенный язык: обязательный фильтр, если язык указан;
- `max_hours >= duration`: обязательный фильтр, если оба значения заданы;
- запас бюджета: до 30 баллов;
- совпадение языка: 20 баллов;
- запас длительности: до 10 баллов;
- релевантные слова описания: до 20 баллов;
- полнота исходных данных: до 10 баллов;
- стабильный tie-break: `id` по возрастанию.

Точные веса можно изменить решением команды, но формула должна быть описана в README и проверяться тестами. Никакой случайности.

## Объяснение

Сначала код формирует список фактов, например:

```json
{
  "within_budget_by_kzt": 150000,
  "format_match": "корпоратив",
  "language_match": "казахский",
  "duration_capacity_hours": 6,
  "description_evidence": "опыт бизнес-форумов"
}
```

Шаблонное объяснение обязательно работает без API. LLM может только переписать эти факты в 1–2 предложения. Он не выбирает кандидатов и не добавляет сведения, которых нет в facts.

## API-контракт

`POST /api/match`

```json
{
  "city": "Астана",
  "date": "2026-11-14",
  "eventFormat": "корпоратив",
  "category": "Ведущий",
  "budgetKzt": 1200000,
  "durationHours": 5,
  "language": "русский"
}
```

Ответ содержит `outcome`, `matches`, `rejectionSummary`, `elapsedMs` и версию алгоритма. Внешнему клиенту не возвращать скрытые ключи или полный внутренний prompt.

## Минимальные тесты

- один запрос дважды — одинаковые ID и порядок;
- тот же запрос на две даты — состав может различаться из-за `busy_dates`;
- занятый кандидат никогда не проходит;
- цена выше бюджета не проходит;
- опциональные язык/длительность реально влияют;
- категория отсутствует в городе;
- категория есть, но все кандидаты отфильтрованы;
- результат ограничен тремя карточками;
- каждая карточка имеет хотя бы два конкретных факта объяснения.
