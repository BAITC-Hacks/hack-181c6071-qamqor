# DATA-1: обязательные сценарии

Из корня репозитория после `npm install`:

```shell
node --test tests/matching.test.mjs
```

Используется встроенный `node:test` и нативная загрузка TypeScript. Проверено на Node.js 25.2.1; старые версии Node без поддержки TypeScript для этой команды не подходят. Новых зависимостей и изменений конфигурации приложения нет.

Тесты импортируют настоящие `loadContractors` и `matchContractors`. Источник данных — `data/hackathon-dataset-anonymized.csv`, 66 профилей. JSON содержит только запросы и фиксированные ожидаемые результаты, а не копию датасета или алгоритма. При изменении официального CSV ожидания нужно пересмотреть вручную.

## Демонстрация

Точные тела запросов доступны в `data/fixtures/matching-scenarios.json` (поле `request`). Их можно ввести в форму или отправить в `POST /api/match`. Во всех запросах формат — `корпоратив`, бюджет — `1500000` ₸, язык и длительность не заданы.

| Сценарий | Город / категория / дата | Ожидаемый результат |
|---|---|---|
| Плотная категория (`dense`) | Астана / Ведущий / 2026-11-14 | MATCHED, 3 карточки: HK-37181, HK-80581, HK-97041 |
| Редкая категория (`rare`) | Алматы / Флорист / 2026-11-15 | MATCHED, 1 карточка: HK-39372; второй флорист занят, busy=1 |
| Пустая выдача (`empty`) | Алматы / Флорист / 2026-11-14 | NO_ELIGIBLE, 0 карточек: из двух флористов один занят, другой не подходит по формату |
| Другая дата (`otherDate`, сравнить с `dense`) | Астана / Ведущий / 2026-11-15 | MATCHED, HK-58385, HK-37181, HK-97041; HK-80581 занят, HK-58385 освободился |

Для редкой категории интерфейс должен показать одну карточку и объяснить: из двух флористов один занят. Тест проверяет число, причины и сообщение matcher; отображение сообщения в браузере требует отдельной UI-проверки. Даты фиксированы по официальному CSV; после их наступления ограничение даты в форме может мешать ручному демо, но автоматические тесты от текущего времени не зависят.

## Наблюдение для Али / владельца UI-2

- База: `feat/ai-data`, `e67be23`.
- Шаги: отправить запрос `rare` через форму (Алматы, Флорист, корпоратив, 2026-11-15, 1500000 ₸).
- Ожидается: одна карточка и пояснение количества/занятости второго кандидата.
- Фактически по коду: matcher возвращает `message` о единственном результате и `rejectionSummary.busy=1`, но ветка MATCHED компонента `SearchResults` не отображает ни сообщение, ни причины. Она выводит общий заголовок и карточку.
- Файл: `src/app/components/SearchForm.tsx`. Наблюдение основано на чтении кода, в браузере не воспроизводилось. Исправление относится к UI-2; в DATA-1 UI не изменяется.

Эти тесты проверяют matcher и загрузчик, но не HTTP-валидацию, DOM, внешний LLM API или production deployment.
